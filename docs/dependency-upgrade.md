# Dependency refresh

This fork moves its development, CI and container baseline to Node 24 LTS (minimum 24.9). The patched Swagger UI dependency remains compatible with Fastify 5, but its dependency graph includes ESM loaded from CommonJS. Jest's documented support for that path requires Node 24.9 or newer. Keeping the old Node 22 Jest runtime made the security candidate fail before the application tests could run; this is not fixed by skipping the tests.

The broken `ts-node-dev` ESM entrypoints are replaced by `tsx watch`. Use `npm run dev`, `dev:mcp` or `dev:mcp:http` as before after installing the current lockfile. These commands may reach external platforms when used; regression CI uses only `make check-no-smoke` and synthetic fixtures.

The lockfile is generated by npm, never edited by hand. Compatible audit updates are applied without `--force`; Swagger UI 6.1.1 is the separately reviewed major upgrade. Runtime and development advisories are recorded separately. Runtime high/critical findings block promotion. A clean runtime dependency audit is not proof that OS packages, optional tools or application behavior have no vulnerabilities.

References: https://jestjs.io/docs/ecmascript-modules#require-of-esm and https://github.com/fastify/fastify-swagger-ui/blob/v6.1.1/index.js
